# Godot C++ GDExtension with OpenCV/ArUco and Quest 3 Android Export

This repository is based on the `godot-cpp` GDExtension template for Godot 4.x, but extends it with an OpenCV dependency managed by Conan and a documented Windows + WSL workflow for exporting an Android APK to a Meta Quest 3.

The main use case documented here is:

1. Build a custom Godot C++ GDExtension.
2. Link OpenCV statically through Conan.
3. Cross-compile the GDExtension to Android `arm64-v8a` in WSL.
4. Package the Godot project as an Android/OpenXR APK on Windows.
5. Sideload the APK to a Meta Quest 3.

---

## Contents

This repository contains:

- Preconfigured C++ source files for GDExtension development in [`src/`](./src/).
- A Godot test project in [`project/`](./project).
- `godot-cpp` as a submodule in `godot-cpp/`.
- An [`SConstruct`](./SConstruct) file for building the extension.
- A [`conanfile.py`](./conanfile.py) that defines the OpenCV dependency.
- GitHub issue templates in [`.github/`](./.github/).
- GitHub CI/CD workflows for building the extension.
- A detailed setup path for Windows + WSL + Android + Quest 3 export.

The repository originally follows the `godot-cpp` template layout. The OpenCV/Conan setup and Quest 3 export workflow are project-specific additions.

## Template usage and renaming

This repository is derived from the Godot C++ GDExtension template. For a new GDExtension project, the usual template renaming steps are:

1. Clone the repository.
2. Initialize `godot-cpp`:

   ```bash
   git submodule update --init --recursive
   ```

3. Change the compiled library name in [`SConstruct`](./SConstruct):

   ```python
   libname = "your_library_name"
   ```

4. Update the loaded library paths in [`project/bin/opencv_aruco.gdextension`](./project/bin/opencv_aruco.gdextension).

   For example, replace old library names such as:

   ```text
   opencv_aruco
   ```

   with your chosen `libname`.

5. Change the `entry_symbol` in the `.gdextension` file.

   Example:

   ```ini
   [configuration]
   entry_symbol = "your_library_init"
   ```

6. Rename the initialization function in [`src/register_types.cpp`](./src/register_types.cpp) to the same name.

7. Optionally rename the `.gdextension` file itself, for example:

   ```text
   project/bin/opencv_aruco.gdextension
   ```

   to:

   ```text
   project/bin/your_extension.gdextension
   ```

For this specific project, the values are:

```text
GDExtension library name: opencv_aruco
Entry symbol:             opencv_aruco_library_init
```

If you change these names, all references must stay consistent across `SConstruct`, the `.gdextension` file, and `register_types.cpp`.

## OpenCV dependency through Conan

OpenCV is managed as a [Conan](https://conan.io) dependency and is built from source. It is statically linked into the GDExtension.

There is no separate prebuilt OpenCV binary and no manual `opencv/build/install/` setup required.

The build flow is:

1. `scons` starts the build.
2. The `SConstruct` checks whether Conan is available.
3. If Conan is missing, the build script can install Conan through Python/pip.
4. A Conan profile is used or generated.
5. Conan builds OpenCV and transitive dependencies into `conan_install/`.
6. SCons reads Conan's build information and links OpenCV into the extension.

The first build is slow because OpenCV is compiled from source. Later builds are much faster because Conan reuses its local cache.

To force a fresh dependency resolve, delete the relevant folder under:

```text
conan_install/
```

or modify/touch:

```text
conanfile.py
```

## Supported build platforms

### Native desktop platforms

For native macOS, Linux, or Windows builds, run SCons normally:

```bash
scons
```

or specify a platform explicitly:

```bash
scons platform=windows
scons platform=linux
scons platform=macos
```

The Conan settings are derived from the SCons build settings.

On Windows/MSVC, the C++ runtime is matched to `godot-cpp`. For example, `use_static_cpp` maps to `/MT` and Conan's static runtime setting.

### Cross-compilation platforms

For Android, iOS, and Web builds, the host machine's default Conan profile is usually not enough. Conan needs a cross-compilation profile describing the target toolchain.

For Android arm64, set `CONAN_HOST_PROFILE` and then build:

```bash
export CONAN_HOST_PROFILE=/path/to/android-arm64-profile
scons platform=android arch=arm64 target=template_debug
```

Without such a profile, the build should abort with an explanatory message.

# Building and sideloading an Android APK to Meta Quest 3

This section documents the Windows + WSL setup used to build the Android `arm64-v8a` GDExtension `.so`, export the Godot project as an Android/OpenXR APK, and sideload it to a Meta Quest 3.

The workflow is split into four tracks:

1. **WSL/Linux build host**: install Linux build tools, Android command-line tools, and Android NDK.
2. **GDExtension build**: cross-compile the native `.so` for Android arm64 using SCons + Conan.
3. **Godot editor on Windows**: configure Android export, OpenXR, export preset, and package the APK.
4. **Quest 3 sideloading**: connect via `adb`, install, and verify the APK.

---

## 1. Architecture of the setup

The final setup uses two different environments:

| Environment | Purpose |
|---|---|
| **WSL / Ubuntu** | Builds the Android GDExtension `.so` using SCons, Conan, OpenCV, `godot-cpp`, and the Android NDK. |
| **Windows / Godot editor** | Exports the APK using Godot's Android export template, Windows JDK, Windows Android SDK, and OpenXR/Meta export options. |
| **Meta Quest 3** | Receives and runs the APK. |

Important consequence:

```text
WSL builds the native library:        *.android.template_debug.arm64.so
Windows Godot packages the APK:       *.apk
Quest 3 runs the APK:                 arm64-v8a Android/OpenXR app
```

The Godot editor does **not** build the GDExtension `.so` for Android automatically. The `.so` must already exist at the path expected by the `.gdextension` file before exporting the APK.

## 4. Track 1 — Set up WSL/Linux build host

### 4.1 Check whether WSL is installed

Open PowerShell on Windows:

```powershell
wsl --version
```

### 4.2 List available Linux distributions

```powershell
wsl --list --online
```

The recorded setup showed `Ubuntu-26.04` as available.

### 4.3 Install Ubuntu in WSL

```powershell
wsl --install -d Ubuntu-26.04
```

During installation, create a Linux username and password:

```text
username: <your-linux-username>
password: <your-own-password>
```

Do not commit real passwords or machine-specific credentials to the repository.

### 4.4 Install base Linux build tools

Open the Ubuntu WSL shell:

```bash
sudo apt update
sudo apt install -y \
  build-essential \
  python3 \
  python3-pip \
  scons \
  git \
  openjdk-17-jdk \
  wget \
  unzip \
  cmake \
  pipx
```

Tool purpose:

| Tool | Purpose |
|---|---|
| `build-essential` | C/C++ compiler toolchain and basic build utilities. |
| `python3`, `python3-pip` | Required by SCons, Conan, and build scripts. |
| `scons` | Build system used by this GDExtension project. |
| `git` | Clone repository and initialize submodules. |
| `openjdk-17-jdk` | Java tooling in WSL. Mainly useful for Android SDK tools. |
| `wget`, `unzip` | Download and unpack Android command-line tools. |
| `cmake` | Required by OpenCV/Conan build dependencies. |
| `pipx` | Optional convenient installation method for Conan. |

## 5. Install Android command-line tools inside WSL

### 5.1 Create Android SDK folder

```bash
mkdir -p "$HOME/Android/sdk/cmdline-tools"
cd "$HOME/Android"
```

### 5.2 Download Android command-line tools

```bash
wget -O commandlinetools-linux.zip \
  https://dl.google.com/android/repository/commandlinetools-linux-14742923_latest.zip
```

Unzip:

```bash
unzip commandlinetools-linux.zip
```

### 5.3 Move command-line tools into the correct SDK layout

The correct final layout is:

```text
$HOME/Android/sdk/cmdline-tools/latest/bin/sdkmanager
```

Move the unpacked folder:

```bash
mv cmdline-tools "$HOME/Android/sdk/cmdline-tools/latest"
```

Check:

```bash
ls "$HOME/Android/sdk/cmdline-tools/latest/bin/sdkmanager"
```

If you accidentally create this nested structure:

```text
$HOME/Android/sdk/cmdline-tools/latest/cmdline-tools/bin/sdkmanager
```

fix it:

```bash
cd "$HOME/Android/sdk/cmdline-tools/latest"
mv cmdline-tools/* .
rmdir cmdline-tools
```

### 5.4 Add Android SDK tools to WSL PATH

Append environment variables to `~/.bashrc`:

```bash
echo 'export ANDROID_SDK_ROOT=$HOME/Android/sdk' >> ~/.bashrc
echo 'export ANDROID_HOME=$ANDROID_SDK_ROOT' >> ~/.bashrc
echo 'export ANDROID_NDK_ROOT=$ANDROID_SDK_ROOT/ndk/23.2.8568313' >> ~/.bashrc
echo 'export PATH=$PATH:$ANDROID_SDK_ROOT/cmdline-tools/latest/bin' >> ~/.bashrc
echo 'export PATH=$PATH:$ANDROID_SDK_ROOT/platform-tools' >> ~/.bashrc
source ~/.bashrc
```

Verify:

```bash
which sdkmanager
sdkmanager --version
```

### 5.5 Install Android SDK platform tools, platform 34, and build-tools 34

```bash
sdkmanager \
  "platform-tools" \
  "platforms;android-34" \
  "build-tools;34.0.0"
```

### 5.6 Install Android NDK 23.2.8568313 inside WSL

```bash
sdkmanager "ndk;23.2.8568313"
```

Verify:

```bash
ls "$ANDROID_SDK_ROOT/ndk/23.2.8568313"
```

Expected path:

```text
/home/<your-linux-username>/Android/sdk/ndk/23.2.8568313
```

This WSL NDK is used for compiling the Android `.so`.

## 6. Track 2 — Build the GDExtension `.so` for Android arm64

### 6.1 Clone the repository

Inside WSL:

```bash
mkdir -p ~/dev
cd ~/dev
git clone --recurse-submodules https://github.com/Pauleano/gdextension_test.git
cd gdextension_test
```

If the repository was cloned without submodules:

```bash
git submodule update --init --recursive
```

### 6.2 Install Conan, if needed

The `SConstruct` can install Conan if it is missing. Manual installation is optional.

If you want to install Conan manually:

```bash
pipx ensurepath
source ~/.bashrc
pipx install conan
```

Verify:

```bash
conan --version
```

### 6.3 Create Conan Android arm64 host profile

Create the profile folder:

```bash
mkdir -p ~/.conan2/profiles
nano ~/.conan2/profiles/android-arm64
```

Paste:

```ini
[settings]
os=Android
os.api_level=24
arch=armv8
compiler=clang
compiler.version=12
compiler.libcxx=c++_static
compiler.cppstd=17
build_type=Release

[conf]
tools.android:ndk_path=/home/<your-linux-username>/Android/sdk/ndk/23.2.8568313
```

Important details:

- `arch=armv8` is Conan's name for Android arm64 / `arm64-v8a`.
- `os.api_level=24` is safe for Quest 3 builds and matches the Android NDK/Godot setup used here.
- `build_type=Release` should remain `Release` even for `target=template_debug`.
- `compiler.libcxx=c++_static` was the recommended starting point.
- Switch to `c++_shared` only if you hit duplicate-symbol or exception-unwinding errors at runtime.

### 6.4 Export the Conan host profile variable

For the current shell:

```bash
export CONAN_HOST_PROFILE=$HOME/.conan2/profiles/android-arm64
```

Optional persistent setting:

```bash
echo 'export CONAN_HOST_PROFILE=$HOME/.conan2/profiles/android-arm64' >> ~/.bashrc
source ~/.bashrc
```

Verify:

```bash
echo "$CONAN_HOST_PROFILE"
cat "$CONAN_HOST_PROFILE"
```

### 6.5 Build the Android arm64 GDExtension library

From the repository root:

```bash
scons platform=android arch=arm64 target=template_debug
```

Expected output path:

```text
project/bin/android/libopencv_aruco.android.template_debug.arm64.so
```

### 6.6 Verify the `.so`

Optional but useful:

```bash
file project/bin/android/libopencv_aruco.android.template_debug.arm64.so
```

Expected: an ELF 64-bit ARM/aarch64 shared object.

Check the entry symbol:

```bash
nm -D project/bin/android/libopencv_aruco.android.template_debug.arm64.so | grep opencv_aruco_library_init
```

### 6.7 Copy the `.so` into the Godot project used by Windows

copy:

```text
WSL:     ~/<repo>/project/bin/android/libopencv_aruco.android.template_debug.arm64.so
Windows: <repo>\project\bin\android\libopencv_aruco.android.template_debug.arm64.so
```

## 7. Track 3 — Configure Godot on Windows for Android/OpenXR export

Important distinction:

- WSL builds the native `.so`.
- Windows Godot exports/packages the APK.
- Godot on Windows needs Windows paths for Java and Android SDK.


### 7.1 Install Windows-side JDK 17

The recorded setup used Eclipse Adoptium JDK 17.

Example path:

```text
C:/Users/<WindowsUser>/AppData/Local/Programs/Eclipse Adoptium/jdk-17.x.x-hotspot
```

The path must point to the JDK home folder containing `bin/java.exe`.

### 7.2 Install Android Studio and Windows Android SDK/NDK

Install Android Studio on Windows.

The recorded setup used Android Studio "Quail 1".

Then install these SDK components in Android Studio:

- Android SDK Platform 34.
- Android SDK Build-Tools 34.0.0.
- Android SDK Platform-Tools.
- Android NDK 23.2.8568313.

Typical Windows SDK path:

```text
C:/Users/<WindowsUser>/AppData/Local/Android/Sdk
```

Typical Windows NDK path:

```text
C:/Users/<WindowsUser>/AppData/Local/Android/Sdk/ndk/23.2.8568313
```

Using the same NDK version family in WSL and Windows reduces ABI/toolchain mismatch risk.

### 7.3 Install Android build template in Godot

Open the project in the Windows Godot editor.

Use:

```text
Project > Install Android Build Template
```

two clicks:

1. First click: download the template.
2. Second click: install the downloaded template.

After installation, the project should contain:

```text
project/android/build/
```

### 7.4 Configure Android export paths in Godot

In Godot:

```text
Editor > Editor Settings > Export > Android
```

Set:

```text
Java SDK Path:
C:/Users/<WindowsUser>/AppData/Local/Programs/Eclipse Adoptium/jdk-17.x.x-hotspot

Android SDK Path:
C:/Users/<WindowsUser>/AppData/Local/Android/Sdk
```

Do not use WSL paths here. Paths such as `//wsl.localhost/...` caused problems in the recorded setup.

### 7.5 Install the OpenXR Vendors plugin 

The plugin should already be present in the repository. If not:

In Godot:

```text
AssetLib > search: OpenXR Vendors
```

Install the plugin. I installed version 5.

The plugin is placed in:

```text
project/addons/
```

### 7.6 Export the APK

In Godot:

```text
Project > Export > Export Project
```

Choose an output path, for example:

```text
C:/Users/<WindowsUser>/Desktop/quest3_test.apk
```

Alternative: use Godot's remote deploy function once the Quest is connected via `adb`.

## 8. Track 4 — Set up Quest 3 and sideload APK

The used Quest 3 was already in developer mode.


### 8.1 Connect Quest 3 via USB-C and authorize debugging

Connect the Quest 3 to the Windows PC using USB-C.

Inside the headset, accept:

```text
Allow USB debugging? > Allow
```

If available, enable:

```text
Always allow from this computer
```

### 8.3 Verify ADB device connection on Windows

In PowerShell:

```powershell
cd C:\Users\<WindowsUser>\AppData\Local\Android\Sdk\platform-tools
.\adb.exe devices
```

Expected output:

```text
List of devices attached
<device-id>    device
```

If the device shows as `unauthorized`, put on the headset and accept the debugging prompt.

### 8.4 Install the APK manually

If you exported an APK manually:

```powershell
.\adb.exe install -r C:\path\to\quest3_test.apk
```

The `-r` flag reinstalls over an existing app.

Alternative: use Godot one-click remote deploy if Godot detects the device.
